# AWS Lightsail Native CLI Flow

Use `aws lightsail` and pass `--profile "$PROFILE" --region "$REGION" --no-cli-pager` on every command. The variables below come from the user's parameters or API queries; do not assume a personal environment.

1. Confirm the account with `aws sts get-caller-identity`. Query the blueprint and bundle at run time: `get-blueprints` (default `debian_13`; Lightsail has no Ubuntu 26.x, so never fall back silently to another OS) and `get-bundles` (default `large_3_0`, 2 vCPU / 8 GB; `medium_3_0`, 4 GB, only for light single-session use). Record the price the API returns. Lightsail is x86 only and bills the full plan price even while the instance is stopped.
2. Pick an availability zone with `get-regions --include-availability-zones`. Use an existing Lightsail key pair (`get-key-pairs`) or import the user's public key with `import-key-pair`; never use `create-key-pair` or `download-default-key-pair`, which return a private key.
3. Create with a unique instance name: `create-instances --instance-names "$NAME" --availability-zone "$ZONE" --blueprint-id debian_13 --bundle-id "$BUNDLE" --key-pair-name "$KEY_NAME" --tags key=ManagedBy,value=agentdesk`. Save the request and response. There is no client token; on a timeout, query `get-instance --instance-name "$NAME"` first and never create again under a new name.
4. Replace the default firewall right after creation; it opens TCP 22 (and 80) to the whole internet. `put-instance-public-ports` replaces all rules in one call, for example `--port-infos 'fromPort=22,toPort=22,protocol=tcp,cidrs=SOURCE/32'`, plus the RDP port for direct access. Confirm with `get-instance-port-states`.
5. Allocate and attach a static IP: `allocate-static-ip --static-ip-name "$NAME-ip"` then `attach-static-ip`. It is free while attached, so always use it; the address then survives stop/start and is the one delivered to the user. A static IP left unattached is billed.
6. Wait until `get-instance-state` is `running`. Read only the host keys with `get-instance-access-details --instance-name "$NAME" --protocol ssh --query 'accessDetails.hostKeys'`; the full response also contains a temporary private key, which must never be printed or saved. Compare the fingerprints with `ssh-keyscan`, write a dedicated known_hosts and connect. The Debian blueprint's initial SSH user is `admin`.
7. Deploy and verify following the main skill flow; keep the native create/query responses and the result record. Check whether `agentdesk info` reads the public address from instance metadata and record the result; when it does not, take the static IP from the API.

Delete resources only when the user authorizes it: `delete-instance --instance-name "$NAME"`, then `release-static-ip --static-ip-name "$NAME-ip"` (an unattached static IP keeps being billed). Confirm both are gone with `get-instance` and `get-static-ip`. Never delete key pairs.

References: [Lightsail CLI](https://docs.aws.amazon.com/cli/latest/reference/lightsail/), [instance firewall](https://docs.aws.amazon.com/lightsail/latest/userguide/understanding-firewall-and-port-mappings-in-amazon-lightsail.html), [static IP](https://docs.aws.amazon.com/lightsail/latest/userguide/lightsail-create-static-ip.html), [pricing](https://aws.amazon.com/lightsail/pricing/).
